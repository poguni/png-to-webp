PNGtoWebP 제품 요구사항 문서 (PRD)

  • 버전: v1.1
  • 작성일: 2026-10-21
  • 상태: 승인됨, 구현 중 (2026-10-21 승인)
  • 플랫폼: 브라우저 웹앱 (Chrome/Edge 기준)
  • 저장소와 배포: GitHub 저장소 + Vercel 자동 배포 (13장)

1. 배경과 문제

앱과 게임을 만들 때마다 다음 작업을 반복하고 있다.

  1. 나노바나나(Gemini 이미지 생성)로 이미지를 만들어 PNG로 저장
  2. 포토샵에서 열어 배경을 투명하게 처리
  3. 이미지 크기를 조절
  4. WebP로 다시 저장

이미지 한 장에 몇 분씩 걸리고, 수십에서 수백 장이 되면 하루 작업 시간 중 큰 부분을 차지한다.

목표: 폴더 하나를 선택하고 설정을 한 번 고르면, 배경 제거부터 자르기, 크기 조절, WebP 저장까지 모든 이미지를 한 번에 처리한다.

2. 목표와 비목표

목표

  • G1. 폴더 안의 PNG/JPG를 WebP로 일괄 변환한다.
  • G2. 포토샵 없이 배경을 투명하게 만든다.
  • G3. 자르기, 크기 조절, 압축 설정을 프리셋으로 저장해 두고 클릭 한 번으로 다시 쓴다.
  • G4. 이미지는 외부 서버로 업로드하지 않고 모두 브라우저 안에서 처리한다.

비목표 (v1에서 하지 않음)

  • 레이어, 브러시 같은 본격적인 이미지 편집 기능
  • 이미지 생성 기능 (나노바나나 API 연동 등)
  • 모바일 브라우저 지원
  • 서버, 계정, 클라우드 저장

3. 사용자와 대표 시나리오

주 사용자: 바이브 코딩으로 웹앱과 게임을 만드는 1인 개발자 (Windows, Chrome/Edge 사용)

#시나리오기대 결과
S1나노바나나로 만든 캐릭터 PNG 30장을 게임 스프라이트용 512×512 투명 WebP로 변환폴더 선택 → "게임 스프라이트" 프리셋 → 실행. output/ 폴더에 30장 저장
S2앱 배경 JPG 10장을 16:9로 잘라 1920×1080 WebP(품질 80)로 변환배경 제거 없이 자르기와 크기 조절만 적용
S3아이콘 1장을 512, 256, 128, 64 크기로 한꺼번에 출력다중 크기 출력으로 icon_512.webp, icon_256.webp 등 생성
S4배경 제거 결과가 어색한 2장만 따로 손보기미리보기에서 해당 이미지만 배경 제거 방식이나 자르기 위치를 바꿔 다시 처리

4. 처리 파이프라인

모든 이미지는 아래 순서로 처리한다. 각 단계는 켜고 끌 수 있다.

불러오기 → ① 배경 제거 → ② 여백 다듬기 → ③ 자르기 → ④ 크기 조절 → ⑤ WebP 인코딩 → 저장

배경을 먼저 제거해야 여백 다듬기와 피사체 중심 자르기가 피사체를 기준으로 동작한다. 그래서 배경 제거가 맨 앞에 온다.

5. 기능 요구사항

우선순위: P0 = v1 필수, P1 = v1에 포함하면 좋음, P2 = 이후 버전

F1. 파일 입력과 일괄 처리 (P0)

  • F1-1. 폴더 선택: File System Access API(showDirectoryPicker)로 폴더를 고른다. 출력 파일을 같은 폴더 안의 output/ 하위 폴더에 바로 쓸 수 있다.
  • F1-2. 드래그 앤 드롭: 파일이나 폴더를 창에 끌어다 놓아도 불러온다.
  • F1-3. 지원 입력 형식: .png, .jpg, .jpeg (대소문자 구분 없음). 그 밖의 파일은 건너뛰고 건너뛴 개수를 알려 준다.
  • F1-4. 하위 폴더 포함 옵션. 켜면 출력 폴더에서도 원래 하위 폴더 구조를 유지한다.
  • F1-5. 파일 목록을 썸네일로 보여 주고, 체크박스로 처리할 파일을 고를 수 있다.
  • F1-6. 진행 상황: 전체 진행률, 현재 파일 이름, 성공과 실패 개수, 남은 예상 시간을 표시한다. 중간에 취소할 수 있다.
  • F1-7. 한 파일이 실패해도 나머지는 계속 처리하고, 끝나면 실패 목록과 이유를 보여 준다.
  • F1-8. ZIP 다운로드 대체 경로: 폴더에 직접 쓰기를 지원하지 않는 브라우저(Firefox 등)에서는 결과를 ZIP으로 내려받는다.

F2. 배경 투명화 (P0)

기본값은 PNG 파일에만 적용한다. JPG에도 적용할지는 옵션으로 고른다.

방식설명적합한 이미지우선순위
AI 자동 제거브라우저에서 ONNX 모델(@imgly/background-removal)을 실행해 피사체를 분리한다. 모델은 처음 한 번만 내려받고 이후에는 캐시를 쓴다.복잡한 배경, 사진풍 이미지P0
단색 배경 제거이미지 가장자리에서 시작해 배경색과 비슷한 픽셀을 투명하게 만든다(플러드 필). 허용 오차(0~100)를 조절할 수 있다.흰색이나 단색 배경의 일러스트, 아이콘P0
가짜 체커보드 제거나노바나나에 "투명 배경"을 요청하면 회색과 흰색 체크무늬를 그려 넣는 경우가 많다. 가장자리에서 두 가지 색을 동시에 인식해 제거한다.나노바나나에서 "투명 배경"으로 생성한 이미지P0
  • F2-1. 경계 다듬기: 경계를 부드럽게 하는 페더(0~5px)와, 경계에 남은 배경색 테두리를 지우는 디프린지를 제공한다. (P1)
  • F2-2. 자동 방식 추천: 가장자리 픽셀을 분석해 단색이면 "단색 배경 제거", 체크무늬 패턴이면 "체커보드 제거", 그 밖에는 "AI 자동 제거"를 고른다. (P1)
  • F2-3. 미리보기에서 투명 영역을 체크무늬, 흰색, 검은색 배경 위에 겹쳐 보며 확인할 수 있다.

F3. 여백 다듬기 (P1)

  • F3-1. 투명한 가장자리를 잘라 피사체에 딱 맞춘다.
  • F3-2. 다듬은 뒤 사방에 여백(px 또는 %)을 더할 수 있다. 게임 스프라이트의 크기를 맞출 때 쓴다.

F4. 자르기 (P0)

  • F4-1. 비율 프리셋: 원본 유지, 16:9, 9:16, 4:3, 3:4, 1:1, 사용자 지정(가로:세로 직접 입력)
  • F4-2. 일괄 처리할 때 자르기 위치: 가운데(기본), 위, 아래, 왼쪽, 오른쪽, 피사체 중심(배경 제거 후 피사체를 둘러싼 영역의 중심, P1)
  • F4-3. 미리보기에서 이미지마다 자르기 영역을 끌어서 옮기거나 크기를 바꿀 수 있다. 바꾼 값은 그 이미지에만 적용한다. (P1)

F5. 크기 조절 (P0)

  • F5-1. 크기 프리셋: 원본 유지, 1920×1080, 1080×1920, 1024×1024, 512×512, 256×256, 128×128, 사용자 지정(가로×세로)
  • F5-2. 맞춤 방식:
    • Contain: 비율을 지키며 안에 맞추고 남는 공간은 투명하게 채움 (기본)
    • Cover: 비율을 지키며 꽉 채우고 넘치는 부분은 잘라 냄
    • Stretch: 비율을 무시하고 늘림
    • 긴 변 기준: 긴 변만 지정한 값에 맞춤 (예: 긴 변 1024px)
  • F5-3. 확대 금지 옵션(기본 켬): 원본이 목표 크기보다 작으면 키우지 않는다.
  • F5-4. 축소할 때 고품질 리샘플링(Lanczos 계열, pica 라이브러리)을 써서 계단 현상과 흐림을 줄인다.
  • F5-5. 다중 크기 출력 (P1): 크기를 여러 개 고르면 파일마다 한 번에 출력한다. 예: hero_512.webp, hero_256.webp

F6. WebP 저장과 압축 (P0)

  • F6-1. 품질 슬라이더 0~100 (기본 80)
  • F6-2. 무손실(Lossless) 모드 켜기/끄기
  • F6-3. 알파 품질 0~100: 투명 영역 경계의 압축 품질 (기본 100)
  • F6-4. 압축 노력도 0~6: 높을수록 파일이 작아지지만 느려진다 (기본 4)
  • F6-5. 품질 프리셋: 고화질(90), 균형(80), 최소 용량(60), 무손실
  • F6-6. 인코더는 libwebp를 WebAssembly로 빌드한 @jsquash/webp를 쓴다. 브라우저 내장 canvas.toBlob('image/webp')로는 무손실, 알파 품질, 노력도를 조절할 수 없기 때문이다.
  • F6-7. 목표 용량 모드 (P2): "200KB 이하"처럼 지정하면 품질을 자동으로 찾아 맞춘다.

F7. 출력 설정 (P0)

  • F7-1. 출력 위치: 원본 폴더 안 output/(기본) 또는 사용자가 고른 폴더
  • F7-2. 파일 이름 규칙: 원래 이름 유지(기본), 접두사와 접미사 추가, 소문자와 하이픈으로 변환(예: My Hero.png → my-hero.webp)
  • F7-3. 같은 이름이 이미 있을 때: 번호 붙이기(기본), 덮어쓰기, 건너뛰기
  • F7-4. 원본 파일은 절대 수정하거나 삭제하지 않는다.
  • F7-5. EXIF 같은 메타데이터는 제거한다. 용량을 줄이고 개인정보 노출을 막기 위해서다.

F8. 미리보기와 결과 비교 (P0)

  • F8-1. 선택한 이미지의 처리 전과 후를 슬라이더로 비교한다.
  • F8-2. 원본 용량, 결과 용량, 절감률(%)과 결과 해상도를 표시한다.
  • F8-3. 설정을 바꾸면 선택한 이미지의 미리보기가 1초 안에 갱신된다. 단, AI 배경 제거는 예외로 한다.

F9. 프리셋 (P1)

  • F9-1. 현재 설정 전체(배경 제거, 자르기, 크기, 압축, 출력)를 이름을 붙여 저장하고 불러온다. 저장은 브라우저의 localStorage에 한다.
  • F9-2. 기본 프리셋을 함께 제공한다:
    • 게임 스프라이트: 체커보드/단색 자동 제거 → 여백 다듬기 + 여백 4px → 1:1 → 512×512 Contain → 품질 85
    • 앱 아이콘 세트: AI 제거 → 1:1 → 512/256/128/64 다중 출력 → 무손실
    • 웹 배경 이미지: 배경 제거 끔 → 16:9 → 1920×1080 Cover → 품질 75
    • 모바일 세로 배경: 배경 제거 끔 → 9:16 → 1080×1920 Cover → 품질 75
  • F9-3. 프리셋을 JSON 파일로 내보내고 가져올 수 있다. (P2)

F10. 처리 리포트 (P2)

  • 처리가 끝나면 파일별 원본과 결과의 용량 및 해상도, 적용된 단계를 CSV로 내려받는다.

6. 비기능 요구사항

항목요구사항
개인정보이미지가 기기 밖으로 나가지 않는다. 네트워크 요청은 앱 파일과 AI 모델을 처음 내려받을 때만 발생한다.
성능 (단색/체커보드 모드)1024×1024 PNG 100장을 중급 PC(4코어, 16GB)에서 60초 안에 처리한다.
성능 (AI 모드)WebGPU를 지원하는 환경에서 1024×1024 기준 장당 3초 이하로 처리한다. 지원하지 않으면 WASM으로 대체하며, 장당 10초 이하를 목표로 한다.
응답성이미지 처리는 Web Worker에서 하며, 처리 중에도 UI가 멈추지 않는다(취소 버튼이 바로 반응).
메모리한 번에 처리하는 이미지 수를 코어 수 이하로 제한해 500장을 처리해도 탭이 멈추지 않는다.
브라우저Chrome/Edge 최신 버전을 완전 지원한다. Firefox와 Safari는 ZIP 다운로드 방식으로 제한적으로 지원한다.
실행 방식개발할 때는 npm run dev로 localhost에서 실행한다. 배포는 GitHub 저장소의 main에 push하면 Vercel이 자동으로 빌드하고 배포한다(13장).
교차 출처 격리Vercel에서 COOP/COEP 헤더를 보내 crossOriginIsolated를 켠다. WebGPU가 없는 PC에서도 AI 배경 제거가 멀티스레드 WASM으로 동작하게 하기 위해서다(AC-11).
오프라인AI 모델을 한 번 내려받은 뒤에는 오프라인에서도 동작한다. PWA 설치 지원은 P2.

7. 기술 스택 (제안)

영역선택이유
빌드/프레임워크Vite + React + TypeScript바이브 코딩에 익숙한 조합이고 설정이 단순함
스타일Tailwind CSS빠른 UI 구성
상태 관리Zustand가볍고, 설정과 큐 상태를 관리하기에 충분함
이미지 디코딩createImageBitmap + OffscreenCanvas브라우저 내장 기능이고 Worker에서 쓸 수 있음
AI 배경 제거@imgly/background-removal브라우저에서 동작하고 WebGPU를 지원함 (라이선스 주의, 10장 참고)
리사이즈pica고품질 Lanczos 리샘플링
WebP 인코딩@jsquash/webplibwebp의 모든 옵션 사용 가능
병렬 처리Web Worker 풀 + comlink코어 수만큼 병렬로 처리

9. 수용 기준 (테스트 가능)

  • AC-1. PNG 5장, JPG 5장, TXT 1장이 든 폴더를 처리하면 output/에 WebP 10장이 생기고 "1개 건너뜀"이 표시된다.
  • AC-2. 원본 폴더의 파일 10개는 처리 전후 수정 시각과 해시가 같다.
  • AC-3. 흰 배경(#FFFFFF) 위에 빨간 원이 있는 PNG를 단색 제거(허용 오차 10)로 처리하면, 결과 WebP의 네 모서리 픽셀 알파값은 0이고 원 중심 픽셀 알파값은 255다. 회색과 흰색 체크무늬 배경 이미지를 체커보드 제거로 처리했을 때도 같은 결과가 나온다.
  • AC-4. 1600×1200 이미지에 16:9 가운데 자르기와 1920×1080 Contain, 확대 금지를 적용하면 결과는 1600×900이다. 확대 금지를 끄면 1920×1080이다.
  • AC-5. 1000×500 이미지에 512×512 Contain을 적용하면 결과는 512×512이고, 위아래에 투명한 여백 128px이 생긴다. Cover를 적용하면 결과는 512×512이고 여백이 없다.
  • AC-6. 같은 이미지를 품질 60으로 변환한 파일이 품질 90으로 변환한 파일보다 작고, 무손실로 변환한 결과는 원본과 픽셀이 완전히 같다.
  • AC-7. 프리셋을 저장하고 새로고침한 뒤 불러오면 모든 설정값이 저장할 때와 같다.
  • AC-8. output/에 같은 이름의 파일이 있을 때 "번호 붙이기"를 고르면 name-1.webp로 저장되고, 기존 파일은 그대로 남는다.
  • AC-9. 100장을 처리하는 도중 취소를 누르면 1초 안에 멈추고, 이미 끝난 파일은 정상적으로 남아 있다.
  • AC-10. 손상된 PNG가 1장 섞여 있어도 나머지는 모두 처리되고, 실패 목록에 해당 파일 이름과 이유가 표시된다.
  • AC-11. Vercel 배포 주소에서 개발자 도구 콘솔에 crossOriginIsolated를 입력하면 true가 나오고, 콘솔에 리소스 차단(COEP) 오류가 없다.
  • AC-12. screenshots/ 폴더에 PNG 파일을 저장한 뒤 git status를 실행해도 그 파일이 나타나지 않는다.

10. 위험과 대응

위험영향대응
@imgly/background-removal이 AGPL-3.0 라이선스Vercel 배포 주소는 누구나 접속할 수 있다. 다른 사람에게 제공하면 저장소가 비공개여도 앱 소스를 공개할 의무가 생긴다.개인용으로 쓰고 주소를 공유하지 않는 동안에는 현실적인 문제가 적다. 공개 전에 결정한다(12장 Q2). MIT 라이선스 모델(예: transformers.js + MODNet)로 바꿀 수 있게 배경 제거 모듈을 인터페이스 뒤로 분리해 둔다.
COOP/COEP 헤더 때문에 외부 리소스가 막힘글꼴이나 AI 모델 파일을 못 불러와 화면이 깨지거나 AI 모드가 동작하지 않음덜 엄격한 credentialless 값을 쓰고, 글꼴은 앱에 포함한다. 배포할 때마다 AC-11을 확인하고, AI 모델이 막히면 모델 파일을 public/models/에 두고 직접 호스팅한다.
AI 모델 용량(약 40~80MB)첫 실행 시 내려받기에 시간이 걸림처음 쓸 때만 내려받고 진행률을 표시한다. 단색/체커보드 모드는 모델 없이 바로 동작한다.
나노바나나의 체크무늬가 균일하지 않음 (노이즈, 그라데이션)체커보드 제거가 덜 될 수 있음허용 오차 조절을 제공하고, 실패하면 AI 모드로 다시 처리하도록 안내한다. 실제 나노바나나 샘플 10장으로 검증한다.
피사체 안에 배경과 같은 색이 있음 (예: 흰 옷)플러드 필이 피사체 안까지 침범플러드 필은 가장자리와 이어진 영역만 지운다. 그래도 문제가 되면 AI 모드를 쓰도록 안내한다.
Firefox와 Safari는 폴더에 직접 쓸 수 없음결과를 원본 폴더에 저장하지 못함ZIP 다운로드로 대체한다. 주 사용 환경은 Chrome/Edge로 명시한다.
대용량이나 대량 처리 시 메모리 부족탭이 멈추거나 종료됨Worker 동시 처리 수를 제한하고, 처리가 끝난 ImageBitmap과 Blob은 바로 해제한다. 썸네일은 작은 크기로 따로 만든다.

11. 검증 방법

  1. 단위 테스트(Vitest): 자르기 영역 계산, 크기 맞춤 계산(AC-4, AC-5), 파일 이름 규칙과 충돌 처리(AC-8), 플러드 필 알고리즘(AC-3)
  2. 통합 테스트: 테스트용 이미지 묶음(단색 배경, 체크무늬 배경, 사진, 손상 파일, 다양한 해상도)을 파이프라인에 통과시켜 결과 크기, 알파값, 용량을 확인
  3. E2E 테스트(Playwright): 파일 불러오기 → 프리셋 선택 → 처리 → 결과 다운로드 흐름 (AC-1, AC-7, AC-9, AC-10)
  4. 수동 검증: 실제 나노바나나 생성 이미지 20장을 처리해 배경 제거 품질을 눈으로 확인하고, 포토샵 작업 결과와 비교
  5. 성능 측정: 6장의 성능 목표를 실제 PC에서 측정해 기록

12. 결정이 필요한 사항

  • Q1. 배경 제거를 JPG에도 기본으로 적용할까? (현재 안: PNG만 기본 적용, JPG는 옵션)
  • Q2. 배포 주소를 다른 사람에게 공유하거나 공개할 계획이 있는가? 있다면 AGPL 라이선스 때문에 앱 소스를 AGPL로 공개하거나 다른 AI 모델로 바꿔야 한다. (현재 안: 개인용으로 쓰고, 공개하기 전에 결정)
  • Q3. 기본 프리셋 4종(5장 F9-2)의 구성이 실제 작업과 맞는가? 자주 쓰는 크기나 품질 값이 있으면 반영한다.

13.5 Vercel 설정

처음 한 번만 하는 작업

  1. Vercel 대시보드에서 Add New → Project를 누르고 GitHub 저장소 PNGtoWebP를 Import한다.
  2. Framework Preset이 Vite로 자동 선택되는지 확인한다. Build Command npm run build, Output Directory dist는 기본값 그대로 둔다.
  3. Settings → Build and Deployment에서 Node.js 버전을 로컬과 같은 메이저 버전(20 이상)으로 맞춘다.
  4. Deploy를 누른다.

이후 배포 방식

  • main 브랜치에 push하면 프로덕션 배포가 자동으로 실행된다.
  • 다른 브랜치에 push하면 미리보기 주소로 배포된다.

환경 변수: 설정할 것 없음

  • 이 앱은 API 키, 서버, 데이터베이스를 쓰지 않으므로 Vercel에 등록할 환경 변수가 없다.
  • 나중에 환경 변수를 추가하더라도 VITE_로 시작하는 변수는 빌드 결과에 그대로 들어가 누구나 볼 수 있다. 그러므로 비밀 값은 넣지 않는다.

  4. D4부터는 AI 배경 제거 모델이 내려받아지고 정상 동작한다.
