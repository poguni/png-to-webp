- 작성일: 2026-10-22
- 버전: v1
- 대상 코드: `main` 브랜치 `cc7752b` (C12 완료 시점, v1.0 출시 직전)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | PNGtoWebP |
| 한 줄 소개 | AI로 만든 PNG·JPG 이미지를 브라우저 안에서 배경 제거, 자르기, 크기 조절을 거쳐 WebP로 한꺼번에 바꿔 주는 웹앱 |
| 대상 사용자 | 나노바나나 같은 이미지 생성 AI로 게임·앱·웹 소스를 만드는 1인 개발자와 디자이너 |
| 개발 기간 | 2026-10-21 ~ 2026-10-22 (커밋 12개) |

| 규모 | 앱 코드 약 4,100줄(TypeScript/React), 테스트 약 880줄(단위 테스트 97개) |

## 2. 목표 및 배경

이미지 생성 AI로 만든 그림을 실제 게임이나 웹에 쓰려면 매번 같은 작업을 반복해야 했다. 포토샵에서 배경을 지우고, 비율에 맞게 자르고, 크기를 줄이고, WebP로 다시 저장하는 일이다. 특히 나노바나나에 "투명 배경"을 요청하면 실제로 투명하지 않고 **회색·흰색 체크무늬를 그려 넣는** 경우가 많아, 이를 지우는 일이 번거로웠다.

이 앱의 핵심 가치는 세 가지다.

1. **한 번 설정으로 폴더 전체 처리**: 수십~수백 장을 같은 규칙으로 한꺼번에 처리한다.
2. **개인정보 보호**: 이미지가 기기 밖으로 나가지 않는다. 모든 처리를 브라우저 안(WebAssembly, Web Worker)에서 한다. 네트워크 요청은 앱 파일과 AI 모델을 처음 받을 때뿐이다.
3. **원본 보존**: 원본은 절대 수정하거나 지우지 않고, 결과는 같은 폴더의 `output/`에 따로 저장한다.

## 4. 기술 스택 및 아키텍처

### 4.1 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드/프레임워크 | Vite 8 + React 19 + TypeScript | 설정이 단순하고 Worker·WASM을 바로 다룰 수 있음 |
| 스타일 | Tailwind CSS 4 | 디자인 시안의 색과 간격을 토큰으로 옮기기 쉬움 |
| 상태 관리 | Zustand | 설정, 파일 목록, 일괄 처리 상태를 하나의 스토어로 가볍게 관리 |
| PNG 디코딩 | `@jsquash/png` | 캔버스를 거치지 않아 반투명 픽셀 색이 바뀌지 않음 |
| WebP 인코딩 | `@jsquash/webp` (libwebp WASM) | 무손실, 알파 품질, 노력도 등 libwebp 옵션을 모두 쓸 수 있음. `canvas.toBlob`으로는 불가능 |
| 리사이즈 | `pica` (mks2013 필터) | 고품질 축소, 투명 픽셀 색 번짐 없음 |
| AI 배경 제거 | `@imgly/background-removal` 1.7.0 (isnet_fp16) | 브라우저에서 WebGPU/WASM으로 동작 |
| ZIP | `JSZip` | Firefox·Safari 대체 경로. 필요할 때만 불러옴 |
| 테스트 | Vitest, 브라우저 검증은 Playwright | |
| 글꼴 | IBM Plex Sans KR, JetBrains Mono (앱에 포함) | COEP 헤더 때문에 외부 글꼴이 막히지 않도록 |
| 호스팅 | GitHub + Vercel | COOP/COEP 헤더 설정, push 배포 |

### 4.2 구조

```
화면 (React)
 ├─ AppHeader ─ PresetControls          프리셋 선택·저장, 처리 시작
 ├─ FileList                            파일 목록, 필터, 체크
 ├─ PreviewPanel ─ useResultPreview     전후 비교, 이미지별 조정
 ├─ SettingsPanel                       배경 제거, 여백, 자르기, 크기, 압축, 출력
 └─ ProcessingView                      진행률, 취소, 실패 목록, ZIP
        │
 store.ts (Zustand)  설정 → convertOptions() → 변환 옵션
        │
 lib/encoder.ts  Worker 풀 (코어 수 − 1, 최대 6, AI는 0번 Worker만)
        │
 workers/encode.worker.ts
   디코딩 → 배경 제거 → 여백 다듬기 → 자르기 → 크기 조절(여러 크기) → WebP 인코딩
        │
 lib/output.ts  output/ 폴더 쓰기  또는  lib/zip.ts  ZIP 내려받기
```

- 계산 로직(자르기 영역, 크기 계획, 플러드 필, 여백, 이름 규칙, 프리셋 병합, 겹침 좌표)은 모두 `src/lib/`의 순수 함수로 두고 단위 테스트를 붙였다.
- 미리보기와 일괄 처리는 같은 `convertOptions()`와 같은 Worker를 쓴다. 그래서 미리보기 결과와 실제 저장 결과가 같다.
- AGPL 라이브러리는 `src/lib/aiBackground.ts` 한 파일에서만 쓴다. 모델을 바꿀 때 이 파일만 고치면 된다.

## 6. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| WebP 인코더로 `@jsquash/webp` 사용 | 브라우저 내장 `canvas.toBlob('image/webp')`는 무손실, 알파 품질, 노력도를 조절할 수 없다. |
| PNG는 캔버스 없이 직접 디코딩 | 캔버스는 프리멀티플라이드 알파 때문에 반투명 픽셀 색을 미세하게 바꾼다. 무손실 결과가 원본과 픽셀 단위로 같아야 한다(AC-6). |
| COOP/COEP의 `credentialless` 사용 | `crossOriginIsolated`를 켜 멀티스레드 WASM을 쓰면서도, AI 모델 CDN이 막히지 않게 하기 위해서다. 글꼴은 앱에 포함했다. |
| 개발 서버 헤더를 `vercel.json`에서 읽기 | 로컬과 배포 환경의 헤더가 어긋나 생기는 문제를 막는다. |
| "확대 금지"는 원본 전체가 목표 안에 들어갈 때만 적용 | F5-3 문장, AC-4(1600×900 그대로), AC-5(Cover 512×512)를 모두 만족하는 유일한 해석이었다. |
| 배경 제거는 가장자리와 이어진 영역만 지움 | 캐릭터 눈의 흰자처럼 안쪽에 갇힌 같은 색을 지키기 위해서다. |
| AI는 투명도(마스크)만 정하고 색은 원본 사용 | 모델 출력 색을 쓰면 색이 탁해진다. |
| 미리보기와 일괄 처리가 같은 변환 경로 공유 | 미리보기와 실제 결과가 달라지는 일을 원천적으로 막는다. |
| 비교 화면에서 결과를 "원본 좌표"로 겹침 | 자르기·Contain 여백·여백 다듬기가 있어도 막대 양쪽 그림이 이어지게 하려고, 결과가 원본의 어느 영역인지 계산하는 함수(`resultPlacement`, `cropInSource`)를 두었다. |
| C9에 WebP 압축 옵션(F6-2~5)을 함께 구현 | 커밋 계획표 어디에도 없던 P0 기능이었고, "앱 아이콘 세트" 프리셋에 무손실이 필요했다. 사용자에게 범위를 확인받고 진행했다. |
| 게임 스프라이트 프리셋에서 1:1 자르기 제외, 확대 금지 끔 | 여백을 다듬은 뒤 1:1로 자르면 가로로 긴 피사체가 잘린다. 512×512 Contain이 정사각형을 만든다. 확대 금지를 켜 두면 다듬어서 작아진 스프라이트가 512로 맞춰지지 않는다. |
| 프리셋 불러오기는 기본값 위에 병합 | 나중에 새 설정이 생겨도 예전 프리셋이 깨지지 않는다(`completeSettings`). |
| Worker 수 = 코어 수 − 1 (최대 6) | 메인 스레드 몫을 남기고, 동시에 디코딩하는 이미지 수를 코어 수 이하로 제한한다(6장 메모리 요구사항). |
| AI 모델은 Worker 하나에만 | Worker마다 약 80MB 모델을 올리지 않도록, 다른 Worker는 AI가 필요하면 `needsAi`로 돌려주고 AI Worker가 다시 맡는다. |
| 취소는 Worker 종료로 | 처리 중인 변환을 기다리지 않고 즉시 멈춰 1초 기준(AC-9)을 지킨다. 변환을 마친 파일은 끝까지 저장한다. |
| ZIP은 압축 없이(STORE) 묶기, JSZip은 필요할 때만 로드 | WebP는 이미 압축되어 다시 압축해도 거의 줄지 않는다. 첫 로딩 크기에도 영향을 주지 않는다. |

## 7. 문제 해결 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| AI 배경 제거가 처음에 모두 실패 | `@imgly/background-removal` 1.7.0이 타입 정의와 달리 `ImageData`를 변환하지 못함 | 라이브러리가 지원하는 원시 RGBA 형식(`image/x-rgba8`) Blob으로 넘김. 캔버스를 거치지 않아 색 손실도 없음 |
| 낮은 창에서 하단 바가 내용을 덮음 (C2) | 레이아웃 높이 계산 | 넓은 화면에서 패널마다 따로 스크롤 |
| 설정 패널이 길어지면 미리보기가 밀림 (C5) | 페이지 전체가 늘어남 | 패널 안에서만 스크롤 |
| 비교 화면 결과 쪽 가장자리에 1px 회색 선 (C8) | 겹친 두 이미지 경계의 안티앨리어싱이 섞임 | 원본도 막대 왼쪽만 보이도록 잘라 아래에 아무것도 없게 함. 상자 크기를 정수로 맞춤 |
| 넓은 창에서 좁은 창으로 바꾸면 이미지가 안 줄어듦 (C8) | flex 항목의 `min-width: auto`가 내용 크기에 고정됨 | 측정용 요소에 `min-w-0` |
| 개발 서버에서 AI를 처음 쓰면 화면이 초기화됨 | Vite가 AI 라이브러리를 처음 만날 때 의존성 재최적화로 새로고침 | 개발 서버 전용 현상이라 앱 코드는 그대로 둠 |
| 여백 단위 선택 상자 때문에 "여백" 글자가 한 글자씩 줄바꿈 (C10) | `w-full`과 `w-auto` 클래스 충돌 | 너비를 150px로 고정 |
| 게임 스프라이트 결과가 512×512가 아니라 409×209 (C10) | 확대 금지 + Contain 규칙(AC-4) | 프리셋에서 확대 금지를 끔. 전역 규칙은 AC-4 때문에 유지 |
| 결과가 원본보다 크면 절감률이 "−-17%"로 표시 (C12) | 부호를 고정으로 붙임 | `formatSaving()`으로 통일, 커지면 빨간 "+17%"와 "늘어난 용량" |
| 2·3번째 push 뒤 Vercel 자동 배포가 안 됨 (D2) | 미확인 | 사용자가 수동 배포로 대응. Vercel Settings → Git의 연결 저장소와 Production Branch 확인을 권장 |

## 8. 보안·개인정보·성능 고려사항

**개인정보**
- 이미지 처리는 모두 브라우저 안에서 한다. 서버, API 키, 데이터베이스가 없다.
- 결과 WebP에는 EXIF 같은 메타데이터가 들어가지 않는다. 픽셀만 인코딩하기 때문이다.
- 원본 파일은 읽기만 한다(AC-2: 처리 전후 해시와 수정 시각이 같음을 확인).

**교차 출처 격리**
- `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: credentialless`. 테스트(`tests/vercel-config.test.ts`)로 헤더가 빠지지 않게 지킨다.

**성능**
- 단색 배경 제거는 1024×1024 한 장에 약 25~44ms다.
- 미리보기는 설정이 0.25초 멈춰 있을 때 갱신하며, 품질을 바꾸면 0.39초 만에 반영된다(목표 1초).
- 일괄 처리: 1024×1024 PNG 100장, 단색 제거, Worker 3개 기준 **12.0초**(목표 60초).
- 취소는 누른 뒤 **0.13초** 만에 멈췄다(목표 1초).
- 처리 중 화면이 가장 오래 멈춘 시간은 0.13초였다.

## 11. 알려진 한계

- **AI 결과 경계에 원래 배경색이 아주 얇게 비칠 수 있다.** 여러 색이 섞인 배경에서 나타난다. 단색 배경은 "자동"이나 "단색"을 쓰면 없다.
- **"자동" 모드는 배경이 복잡하면 AI로 넘어간다.** AI를 빼고 색 제거만 하는 선택지는 없다(게임 스프라이트 프리셋도 같음).
- **확대 금지가 켜져 있으면 여러 크기 출력의 파일 이름과 실제 크기가 다를 수 있다.** 예: `photo_1920x1080.webp`가 731×411.
- **이미지별 조정은 프리셋에 저장되지 않고**, 폴더를 다시 불러오면 사라진다.
- **ZIP 경로는 결과를 메모리에 모은다.** 매우 많은 파일을 처리하면 메모리를 많이 쓴다. 실제 Firefox·Safari에서는 아직 확인하지 않았다(Chromium에서 시뮬레이션으로 확인).
- **AI 모드 장당 시간(PRD 6장: WebGPU 3초, WASM 10초)은 정식으로 측정하지 않았다.**
- **`dist/`에 쓰이지 않는 onnxruntime WASM 파일(23.9MB)이 포함된다.** 실행 때는 CDN에서 받으므로 사용자 다운로드량에는 영향이 없다.
- 브라우저 보안 때문에 상단에 폴더 전체 경로를 보여 줄 수 없다(폴더 이름만 표시).
- Vercel 자동 배포가 일부 push에서 동작하지 않은 원인을 아직 찾지 못했다.
- **라이선스**: `@imgly/background-removal`은 AGPL-3.0이다. 주소를 다른 사람과 공유하기 전에 PRD 12장 Q2를 결정해야 한다.
